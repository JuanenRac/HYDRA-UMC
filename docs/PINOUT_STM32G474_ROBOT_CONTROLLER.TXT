================================================================================
     ROBOT CONTROLLER BOARD - STM32G474RET6 PINOUT (LQFP-64, 10x10mm)
                    PROPOSED - pre-schematic pin allocation
================================================================================
STATUS: PROPOSED. FDCAN1 (this chip's uplink to STACK A) and the TIM1/TIM8
STEP channels below were checked against Table 12 (pin definition) of
docs/datasheets/STM32G474RET6.pdf and are real, confirmed alternate
functions on the LQFP-64 package. The remaining plain-GPIO assignments
(DIR/ENABLE/endstops/power-good sensing) follow this chip's well-established
standard LQFP-64 port layout (full Port A/B, most of Port C, PD2 only,
matching every public STM32G474 LQFP-64 reference design, incl. ST's own
Nucleo-G474RE) but were not re-verified pin-by-pin against Table 12 the way
the H745 file was - re-confirm in STM32CubeMX before schematic capture.
Debug (SWD: PA13/PA14), boot, and power pins are out of scope here.

This board is one of up to 8, identical, one per robot - docs/
architecture.md section 1 (Tier 1), README.md section 12.

--------------------------------------------------------------------------------
1. FIELDBUS - 2 of this chip's 3 FDCAN peripherals in use
--------------------------------------------------------------------------------
1a. FDCAN1 - uplink to the Kinematic Brain's STACK A bus (this board's own
"STACK A IN" connector, docs/PINOUT_STACKA_CONNECTOR.TXT)
Pin  | Signal      | AF   | Notes
-----+-------------+------+-------------------------------------------------
PB8  | FDCAN1_RX   | AF9  | CONFIRMED pin (Table 12). Deliberately NOT
PB9  | FDCAN1_TX   | AF9  | PA11/PA12 (also valid FDCAN1 pins on this chip)
     |             |      | to keep PA11/PA12 free for USB/other use and to
     |             |      | leave PA8-PA11 as one contiguous TIM1 block for
     |             |      | STEP generation - section 3 below.
PG7  | CAN1_STBY   | GPIO | Transceiver standby/enable (matches the
     |             |      | Kinematic Brain's own CAN1_STBY convention,
     |             |      | docs/PINOUT_STM32H745_KINEMATIC_BRAIN.TXT §2)

1b. FDCAN2 - downlink relay to this robot's own URTC Tool Head (README.md
section 12, docs/architecture.md section 5)
Pin  | Signal      | AF   | Notes
-----+-------------+------+-------------------------------------------------
PB5  | FDCAN2_RX   | AF9  | Standard G474 mapping - re-verify in CubeMX
PB6  | FDCAN2_TX   | AF9  | Standard G474 mapping - re-verify in CubeMX
PG8  | CAN2_STBY   | GPIO | Transceiver standby/enable, second transceiver

(The 3rd onboard FDCAN peripheral, FDCAN3, is unused - reserved for future
use, e.g. a second relay hop if a robot ever needs more than one URTC head.)

2. 6x TMC5160A STEPPER DRIVERS - one per robot axis (axis numbering is

(docs/PINOUT_STM32H745_KINEMATIC_BRAIN.TXT section 3) for the same reason:
fits a tight LQFP-64 pin budget, and keeps the two boards' driver interface
consistent so firmware/HAL code can be shared between them.

PA2  | DRV_DIAG_OR  | GPIO | Wired-OR fault/stallGuard line, all 6 drivers -

4. LOCAL POWER SUPPLY - this board's own 5V and 3.3V regulation
--------------------------------------------------------------------------------
Per the user's own spec, this board generates its OWN 5V and 3.3V locally
rather than relying on the STACK A bus's +5V_BUS pins (docs/
PINOUT_STACKA_CONNECTOR.TXT section 1, which documents that rail as
auxiliary/optional for exactly this reason). PROPOSED power architecture:

    STACK A +24V_BUS (10 pins) --+--> local 24V->5V buck --> local +5V rail
                                  |     (logic, drivers' VS if needed)
                                  +--> local 24V->3.3V buck/LDO --> +3.3V
                                        (MCU core, CAN transceivers)

This gives each Robot Controller Board electrical independence from
whatever the other 7 boards on the same bus are doing, and from the
Kinematic Brain's own local rail regulation - only the 24V supply and GND
are truly shared/critical; 5V and 3.3V are each board's own problem exactly
because the user asked for it that way.

Pin  | Signal        | Notes
-----+---------------+---------------------------------------------------
PB7  | PGOOD_5V      | Power-good sense from the local 5V regulator
PB3  | PGOOD_3V3     | Power-good sense from the local 3.3V regulator
PC13 | STATUS_LED    | Board-alive indicator (bring-up/diagnostic use)

5. ROBOT CONNECTORS - 2x 24POS 3.00mm Micro-Fit 3.0 - PINOUT PENDING
--------------------------------------------------------------------------------
The user has explicitly said the pin-by-pin mapping for these two
connectors will be specified separately ("que ya te especificare pinout").
Nothing below is a real pinout - it only records what's already decided so
the eventual real spec has somewhere to land.

  - Connector type: Molex Micro-Fit 3.0, 24-position, 3.00mm pitch, 2x -
    CONFIRMED (user-specified part family/pin count).
  - Signals likely to be carried (not yet mapped to specific pins): the 6x
    TMC5160A motor-phase outputs (section 2 above - these come directly off
    each driver's own integrated FET half-bridges, NOT through additional
    MCU GPIOs), the 6x endstop signals (section 3 above, if endstops are
    robot-side rather than board-side), and GND/sense returns. Whether all
    6 axes' phases split 3-per-connector, or the split follows some other
    robot-specific grouping, is part of what the user will specify - NOT
    guessed here per this project's own established convention (see
    memory: don't invent what a spec-less variant should be).
  - Do not assign J1/J2 pin numbers, designators beyond "Connector 1" /
    "Connector 2", or infer axis groupings ahead of that spec.
