        KINEMATIC BRAIN - STM32H745ZIT6 PINOUT (LQFP-144, 0.5mm pitch)
                    PROPOSED - pre-schematic pin allocation

STATUS: PROPOSED. Every pin below was checked against Table 8 (pin/ball
definition) of docs/datasheets/STM32H745ZIT6.pdf to confirm it physically
exists on the LQFP-144 package (NOT all pins named PFx/PGx/PHx/PIx do - this
package breaks out full Port A-E, only PART of Port F and Port G, and NO
Port H or Port I at all - those only exist on the larger UFBGA176/LQFP176/
LQFP208/TFBGA240 variants of this same die). The peripheral instance choices
(which SPI, which FDCAN, which TIM channel) are real, confirmed alternate
functions for this chip. The exact GPIO chosen for each plain on/off signal
(DIR, ENABLE, endstops, pump/valve/SSR drives) is a reasonable, budget-
checked but NOT hardware-verified choice - re-confirm against Table 8/
Table 9 (alternate functions) in STM32CubeMX before finalizing schematic
silkscreen. Clock source pins (OSC_IN/OUT, boot pins, debug SWD, power
pins) are out of scope for this file - already flagged as TODO in
docs/COMPILE_STM32H745.TXT section 6.

Total distinct GPIO pins used below: 72 of the ~75 confirmed-available
general-purpose pins on this package (3 spare - PG8, PG9, PG10 - see
section 9). This is intentionally tight, and it is the reason several
design choices below (SPI daisy-chaining, a shared fault line) exist: a
naive "one pin per signal, no sharing" allocation for everything the user
asked for does NOT fit in the pins this package actually has broken out.

3. 6x TMC5160A STEPPER DRIVERS - X, Y1, Y2, Z, E0, E1
--------------------------------------------------------------------------------
PROPOSED design choice: the 6 TMC5160A are wired as one SPI DAISY CHAIN
(each driver's SDO feeds the next driver's SDI, standard TMC5160 multi-axis
technique - same principle used on e.g. Duet3D's own multi-axis boards) with
ONE shared chip-select for all 6, instead of 6 separate CS lines. This is
what makes the pin budget in this file fit at all - see the file header.
Firmware addresses all 6 drivers in a single long SPI transaction instead of
6 short ones; functionally equivalent, one more reason to prefer it (fewer,
larger SPI transactions instead of many small ones on a 480 MHz CM7 core).

3a. Shared SPI bus (SPI4)
Pin  | Signal            | AF   | Notes
-----+-------------------+------+---------------------------------------------
PE2  | SPI4_SCK          | AF5  | CONFIRMED pin
PE6  | SPI4_MOSI         | AF5  | CONFIRMED pin - chain head (into driver 1's
     |                   |      | SDI)
PE5  | SPI4_MISO         | AF5  | CONFIRMED pin - chain tail (out of driver
     |                   |      | 6's SDO)
PA12 | DRV_CS_ALL         | GPIO | Shared chip-select, all 6 drivers
PA2  | DRV_DIAG_OR        | GPIO | Wired-OR fault/stallGuard line from all 6
     |                   |      | drivers' DIAG0 output (open-drain OR gate,
     |                   |      | or simple diode-OR). Tells firmware "one of
     |                   |      | the 6 needs attention"; firmware then polls
     |                   |      | each driver's own SPI status register over
     |                   |      | the shared bus above to find out which one.
     |                   |      | Chosen over 6 dedicated DIAG lines for the
     |                   |      | same pin-budget reason as the daisy chain.

9c. FREE / UNASSIGNED - 3 pins, all on Port G:

    PG8   - free, general-purpose
    PG9   - CM7's own FreeRTOS smoke-test blink LED (firmware/mcu_stm32h745/
            CM7/STM32H745ZI_CM7_main.c) - not a real peripheral signal, just
            claims a genuinely-spare pin instead of colliding with a real
            one the way the pre-pinout placeholder (PB0, now X_DIR) did.
    PG10  - CM4's own FreeRTOS smoke-test blink LED (firmware/mcu_stm32h745/
            CM4/STM32H745ZI_CM4_main.c) - same reasoning as PG9 above
            (previous placeholder was PE0, now PUMP1).

    Only PG8 is genuinely uncommitted. Keep it spare rather than pre-
    committing; the user has already twice said "se me habra olvidado
    cosas" - this is the margin for whatever that turns out to be. If more
    spare pins are needed later, the only places to find them are (a)
    retiring the two smoke-test LEDs above once real application tasks
    exist, or (b) revisiting a design choice in sections 3-4 (the shared
    DIAG line or the SPI daisy-chain) that traded pin count for a single
    shared line - see the file header for why those trades were made.

10. RECONCILIATION WITH PREVIOUSLY-DOCUMENTED SPECS
--------------------------------------------------------------------------------
This message's requirements changed 4 things README.md section 8 (and the
BOM it was derived from) previously said. All 4 are updated in README.md /
hardware/PCB/kinematic_brain_stm32h745/BOM.TXT alongside this file:

  - Axes: generic 6-axis "X, Y, Z, A, B, C" -> concrete "X, Y1, Y2, Z, E0,
    E1" (dual-Y gantry + 2 tool/extruder axes). This file's section 3 uses
    the new names.
  - Valve/pump channels: "16x Low-Side Switching Channels (8 valves + 8
    pumps)" -> 20 total (8+2 pumps, 8+2 valves) - sections 6-7 above.
  - Heated bed: "PWM controlled, 24V bus" -> solid-state relay switching
    230VAC mains, with 2 dedicated thermistors (previously "4x" shared
    across unspecified use) - section 8 above. This is the one safety-
    relevant change: 230VAC mains switching needs real isolation on the
    PCB (creepage/clearance, opto-isolated SSR trigger, mains-rated
    connector and trace spacing) that a 24V PWM design would not have
    needed. Flag this to whoever lays out the PCB - it is not a drop-in
    swap of the same footprint.
  - STACK A connector: "Heavy-copper shrouded connector, 2.54mm pitch"
    (no pin count) -> 40-pin, full pinout in
    docs/PINOUT_STACKA_CONNECTOR.TXT.
